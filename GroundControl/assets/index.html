Stage

Tokens, not words

The model never sees letters. Text is cut into tokens (word pieces) and each one becomes an ID. "matrix_text" is two tokens; the whole fixed prompt is about 750.

matrix_text(text)

The KV cache

Reading the prompt (prefill) runs at about 5 tokens/s here, so 750 tokens would cost 2.5 minutes. The prompt starts with the same fixed text every time, so llama.cpp keeps its attention keys/values from the last request and only reads the new command: about 35 tokens, 7 seconds.

4-bit weights (Q4_0)

Qwen3-1.7B has 1.7 billion weights. Stored as 16-bit floats that's 3.4 GB; Q4_0 packs blocks of 32 weights into 4-bit integers with one scale each, so the whole model is 1.06 GB and fits next to everything else in the UNO Q's 4 GB.

Why the JSON is always valid

The plan's JSON schema is compiled into a grammar. At every step llama.cpp masks out tokens that would break it, so the model can only pick a real skill name, a legal icon, a bpm in range. ⚑ marks tokens where the model's favourite was masked.

Two brains

The LLM is a planner: about 20 to 35 seconds per command. It never drives in a loop. Timing-critical work (the beat clock, stopping, the watchdog) is deterministic code that reacts in milliseconds. "stop" never touches the model.

The duet

The model writes a short dance score (bpm, sections, moves, mode). A compiler turns it into timed keyframes, and a conductor fires them to both robots against one clock, early by each robot's measured latency. Then it measures how far off each move landed.
